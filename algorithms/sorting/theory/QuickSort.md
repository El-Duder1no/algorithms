# Quick Sort

**Quick Sort** — это алгоритм сортировки, который использует принцип «разделяй и властвуй». 

Выбор опорного элемента (или **pivot**) — один из ключевых аспектов алгоритма быстрой сортировки. Он влияет на эффективность работы алгоритма, определяя, как именно будет происходить разбиение массива.

Разбиение массива (или **partition**) — это ключевая операция в этом алгоритме, на которой основан принцип "разделяй и властвуй". После выбора опорного элемента, массив делится на две части: элементы, меньшие опорного, и элементы, большие опорного. В результате разбиения опорный элемент оказывается на своем окончательном месте, а затем рекурсивно сортируются подмассивы слева и справа от него.

## Стратегии выбора опорного элемента

Существует несколько стратегий выбора опорного элемента в быстрой сортировке:
1.  Первый — выбрать первый элемент массива в качестве опорного.
2.  Последний — выбрать последний элемент массива.
3.  Случайный — выбрать случайный элемент массива.
4.  Медиана из трёх — выбрать среднее значение среди первого, среднего и последнего элемента массива.

### Какая стратегия эффективнее?

Выбор медианы из трёх — более продвинутая и часто более эффективная стратегия, чем остальные, так как она помогает снизить вероятность худших случаев, связанных с уже отсортированными или почти отсортированными массивами.
-   **Балансировка разбиения**: Когда опорный элемент выбирается случайным образом, или мы всегда берем крайний элемент, вероятность того, что массив будет разбиваться неравномерно, значительно возрастает. Если массив уже отсортирован или почти отсортирован, выбор крайнего элемента как опорного может привести к худшему времени работы $O(n^2)$. Медиана из трех элементов уменьшает эту вероятность.
-   **Устойчивость к худшим случаям**: Стратегия медианы из трех уменьшает вероятность того, что опорный элемент окажется на одном из краев массива, особенно в случае уже отсортированных данных. Это помогает поддерживать хорошую производительность даже при неблагоприятных входных данных.
-   **Сложность**: Хотя для вычисления медианы из трех элементов нужно выполнить несколько сравнений, это не существенно увеличивает сложность алгоритма. Время работы остаётся $O(n \log n)$ в среднем.

### Псевдокод функции выбора медианы из трёх элементов

    procedure medianOfThree(A, n)
	    A — список
	    n — размер списка
	    
        begin = A[1]
        mid = A[n / 2]
        end = A[n]
        if begin > mid then
            swap begin and mid
        endif
        if begin > end then
            swap begin and end
        endif
        if mid > end then
            swap mid and end
        endif
        return mid
    end procedure

## Стратегии разбиения

Существует несколько способов реализации этой операции, и разные методы разбиения могут влиять на эффективность алгоритма в зависимости от структуры входных данных.

Основные Стратегии разбиения:

**1. Метод Ломуто (Lomuto Partition Scheme)**

Этот метод является простым и часто используется в реализации быстрой сортировки, хотя он может быть менее эффективным по сравнению с методом Хоара.

**Описание алгоритма:**

1.  Выбирается опорный элемент (часто последний элемент массива).
2.  Инициализируется два указателя: один — для отслеживания элементов, меньших опорного, и второй — для прохода по массиву.
3.  Проходим по массиву и перемещаем элементы меньше опорного в левую часть массива.
4.  В конце переставляем опорный элемент на его окончательное место, то есть на позицию, на которой все элементы слева от него меньше, а все элементы справа — больше.

**Псевдокод метода Ломуто:**

    procedure LomutoPartition(A, low, high)
        A — массив
        low — индекс первого элемента
        high — индекс последнего элемента

        pivot = A[high]  // Опорный элемент
        i = low - 1      // Индекс меньших элементов
        for j = low to high - 1 do
            if A[j] < pivot then
                i = i + 1
                swap A[i] and A[j]
            end if
        end for
        swap A[i + 1] and A[high]
        return i + 1
    end procedure

**2.  Метод Хоара (Hoare Partition Scheme)**
Этот метод является более эффективным и часто используется в реальных реализациях быстрой сортировки. Он работает быстрее, так как на каждом шаге алгоритм может обрабатывать большие части массива и избегать множества перестановок.

**Описание алгоритма:**

1.  Выбирается опорный элемент (чаще всего первый или средний элемент массива).
2.  Используются два указателя: один с левого конца массива, а второй с правого.
3.  Указатели перемещаются внутрь массива, пока не найдутся элементы, которые нужно обменять.
4.  После нахождения таких элементов они меняются местами, и процесс продолжается до тех пор, пока указатели не встретятся.

**Псевдокод метода Хоара:**

    procedure HoarePartition(A, low, high)
        A — массив
        low — индекс первого элемента
        high — индекс последнего элемента

        pivot = A[low]  // Опорный элемент
        i = low - 1
        j = high + 1
        while true do
            repeat
                j = j - 1  // Ищем элемент, больше опорного
            until A[j] <= pivot
            repeat
                i = i + 1  // Ищем элемент, меньше опорного
            until A[i] >= pivot
            if i < j then
                swap A[i] and A[j]
            else
                return j
            end if
        end while
    end procedure

**3.  Метод Три Хоара (Three-way Partition Scheme)**
Метод Три Хоара используется для работы с массивами, содержащими много одинаковых элементов. Этот метод улучшает производительность быстрой сортировки в случаях, когда массив содержит большое количество дубликатов.

**Описание алгоритма:**
1.   Алгоритм работает аналогично методу Хоара, но с добавлением дополнительной проверки для элементов, равных опорному.
2. В процессе разбиения создаются три области:
    -   Элементы, меньшие опорного.
    -   Элементы, равные опорному.
    -   Элементы, большие опорного.
3.  Это разбиение позволяет избежать ненужных сравнений и перестановок для элементов, равных опорному.

**Псевдокод метода Три Хоара:**

    procedure ThreeWayPartition(A, low, high)
        A — массив
        low — индекс первого элемента
        high — индекс последнего элемента
        pivot = A[low]  // Опорный элемент
        
        lt = low        // Индекс для элементов меньше опорного
        gt = high       // Индекс для элементов больше опорного
        i = low         // Текущий индекс для проверки элементов
        while i <= gt do
            if A[i] < pivot then
                swap A[lt] and A[i]
                lt = lt + 1
                i = i + 1
            else if A[i] > pivot then
                swap A[i] and A[gt]
                gt = gt - 1
            else
                i = i + 1
            end if
        end while
        return lt, gt  // Возвращаем индексы границ
    end procedure

### Какая стратегия эффективнее?

Выбор метода разбиения зависит от особенностей данных, с которыми работает алгоритм.

-   Метод Ломуто прост и интуитивно понятен, но может быть менее эффективным на больших и уже отсортированных массивах.
-   Метод Хоара дает более эффективное разбиение, но требует более сложной реализации.
-   Метод Три Хоара подходит для массивов с множеством одинаковых элементов и способен значительно повысить производительность в таких случаях.

# Сложность

-   Время: 
    -   **Лучший случай**: $O(n \log n)$ — если опорный элемент делит массив на две равные части. В этом случае рекурсия проходит $\log n$ уровней, и на каждом уровне выполняются $n$ сравнений.
    -   **Средний случай**: $O(n \log n)$ — в среднем, даже если опорный элемент не делит массив идеально пополам, разделение остаётся достаточно сбалансированным, чтобы обеспечить логарифмическую глубину рекурсии.
    -   **Худший случай**: $O(n^2)$ — если на каждом шаге выбирается самый маленький или самый большой элемент в качестве опорного, что приводит к очень несбалансированным разделениям (массив разделяется только на одну часть, а вторая остаётся пустой), что делает сложность линейной по количеству элементов и квадратичной по времени работы.
-   Память: $O(\log n)$ для рекурсии.
